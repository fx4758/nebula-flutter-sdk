# Nebula Flutter SDK 0.1.0-rc2

- Channel: Release Candidate / immutable Git tag
- Planned tag: `v0.1.0-rc2`
- Registry publication: **NO** (`publish_to: none`)
- Public API surface: **131 -> 131 during packaging**; RC1 was 127 and canonical Auth V2 added four symbols before RC2 packaging
- Release Story: `NEBULA-SDK-RELEASE-002`

## Release content

RC2 contains all RC1 capabilities plus canonical Mobile Auth V2: preserved PHONE/SMS, typed EMAIL/password, EMAIL verification/register/reset, typed Apple/Google authorization-code login, and stable invalid-credentials mapping.

Provider authorization-code acquisition and provider credentials/configuration are not SDK responsibilities. Consumer Apps integrate those through App-owned adapters.

## Release gates

The exact release candidate must pass governance CI, release self-check/regression, API surface 131, Platform boundary guard, secret scan, format, analyzer, full SDK tests and smoke. Independent official exact-head review is required.

Canonical publication must preserve the exact reviewed candidate. Only after post-publication governance succeeds may Coordinator publish `v0.1.0-rc2` to that exact SHA. The tag-triggered `release-gate` must then pass before RC2 is declared released.

## Consumer rule

Consumers pin the immutable tag or its resolved commit through their own dependency governance. Floating branches and `package:nebula_sdk/src/**` imports are not supported integration paths.
