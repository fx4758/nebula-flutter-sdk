# Nebula Flutter SDK 0.1.0-rc1

- Channel: Release Candidate / immutable Git tag
- Planned tag: `v0.1.0-rc1`
- Registry publication: **NO** (`publish_to: none`)
- Public API surface: **127 -> 127**, no packaging delta
- Release Story: `NEBULA-SDK-RELEASE-001`

## Release content

RC1 freezes the first multi-app SDK identity containing installation bootstrap/proof foundations, session auth, Runtime Config, Analytics, Error Reporting, durable Error Reporting persistence, mobile observability transport/composition/lifecycle, common transport/error/logging/storage ports and governance/test utilities.

## Mobile Observability V1

Public App integration is through `NebulaMobileObservability.create(...)`. Apps receive `NebulaAnalytics`, `NebulaErrorReporting` and `flush()` only. Durable Error Reporting storage, stable `report_id`, retry, trust recovery, partial ACK handling, trusted InstallationProof identity and server `ingested_at` remain internal/server-owned as applicable.

## Release gates

The exact release candidate must pass governance CI, release-gate self-check, API surface 127, Platform boundary guard, secret scan, format, analyzer, full SDK tests and smoke. Independent official review is required.

The release PR must land fast-forward-only so canonical `main` is byte-for-byte the reviewed candidate. Only after post-merge governance succeeds may Coordinator publish `v0.1.0-rc1` to that exact SHA. The tag-triggered release workflow must then pass before RC1 is declared released.

## Consumer rule

Consumers must pin the immutable tag or its resolved commit through their existing dependency governance. Floating branches and `package:nebula_sdk/src/**` imports are not supported integration paths.
